# NEXUS — отчёт об аудите, исправлениях и доработке

Дата: 2026-11-26 · Версия: **0.1.0** · Платформа: CachyOS (niri/Wayland), Tauri 2.12.7
Исходный baseline: UI-реализация по референсу (~2 700 строк). Итог: ~16 700 строк
исходников (canvas 6 929, settings 3 459, components 3 170, lib 3 052 + остальное).

Документ соответствуют структуре из ТЗ (раздел 10). Сырые результаты прогонов —
[docs/test-results.txt](test-results.txt), security-аудит — [docs/security-audit.md](security-audit.md).

---

## Исправлено

1. **Удаление документов и папок** — реализована полноценная система:
   - удаление через контекстное меню, кнопку в шапке Workspace Explorer, Command Palette и клавишу Delete;
   - множественное выделение (Ctrl/Cmd+клик, Shift+клик диапазоном), индикатор «Выбрано: N»;
   - подтверждение удаления с выбором для папок: «удалить папку и содержимое» (каскад) или
     «удалить папку, перенести содержимое выше», чекбокс «больше не спрашивать»;
   - Undo последнего удаления из тоста, а также Ctrl+Z / Ctrl+Shift+Z (глобально, вне редактора);
   - корректное закрытие вкладок и переключение активной вкладки, очистка выделения;
   - Explorer/поиск/списки/backlinks/Canvas обновляются без перезапуска; уже удалённый
     элемент не вызывает ошибок (проверки существования во всех операциях).
2. **Контекст Delete** — удаление срабатывает только когда фокус не в input/contentEditable
   и есть выделение; Backspace элементы не удаляет; во время inline-переименования клавиши
   обрабатывает поле ввода.
3. **Потеря состояния при перезапуске** — workspace, заметки, вкладки, панели и настройки
   персистятся (zustand persist, debounce 250 мс, flush на visibilitychange/beforeunload).
4. **Ошибки данных и регрессии UI**, найденные по ходу аудита:
   - утечка дизайн-токенов: класс `text-left` (выравнивание) конфликтовал с цветовым токеном
     `left` и красил текст в цвет фона — токены переведены в `side.left/right`;
   - даты рендерились в системной локали независимо от языка приложения — форматирование
     привязано к настройке языка;
   - после удаления активной вкладки открывался список вместо соседней вкладки — исправлено;
   - `package.json` версия `0.0.0` расходилась с About/Tauri — приведено к `0.1.0`;
   - autosave-интервал и `revealActive` из настроек не были подключены — реализованы;
   - битые/устаревшие localStorage-данные могли уронить запуск — добавлены валидация,
     fallback на дефолты и Error Boundary;
   - статичная заглушка Canvas заменена реальным модулем; удалён мёртвый код (`Views.tsx`),
     неиспользуемые зависимости Rust (`serde`, `serde_json`), добавлены `.gitignore`-правила.
5. **Безопасность** — закрыты все найденные аудитом проблемы (раздел «Безопасность»).
6. **Разное**: закрытие вкладок кнопкой, корректные заголовки вкладок после переименования,
   guard внешних ссылок, устранены «мёртвые» кликабельные элементы, добавлены empty states,
   консольных ошибок нет на всех сценариях.

## Реализовано

### Анимации и плавность (п.2 ТЗ)
- Длительности 140–240 мс, easing `cubic-bezier(0.22,0.61,0.36,1)`, только transform/opacity/цвета.
- Плавное сворачивание/разворачивание сайдбаров и появление вкладок, модальных окон,
  контекстных меню, тостов, палитры, смена разделов и темы, раскрытие папок
  (`grid-template-rows 0fr→1fr`), hover/focus/active/disabled переходы.
- Настройка «Анимации» и режим движения (system/full/reduced) + `prefers-reduced-motion`;
  все анимации отключаются одним CSS-правилом.

### Canvas — интерактивная доска (п.3 ТЗ)
- Бесконечный холст (Konva): pan/zoom/fit/reset, сохранение viewport; инструменты
  Select/Hand/Sticky/Text/Shapes/Connector/Draw/Image/Document/Eraser.
- Объекты: создание, выбор (клик/shift/marquee), перемещение, resize/rotate, цвета, текст,
  шрифт, толщина, прозрачность, дублирование, удаление, copy/paste, слои, выравнивание,
  группировка/разгруппировка.
- Соединения с привязкой к объектам; редактирование цвета/толщины/направления; отдельное удаление.
- Несколько канвасов (создание/переименование/удаление/переключение), автосохранение в
  `nexus:canvas:v1`, undo/redo (30 шагов), контекстное меню, поиск объектов, экспорт PNG.
- Интеграция: карточки документов ссылаются на реальные заметки и открывают их,
  удалённые документы показываются как «Document deleted»; команда «Create new canvas»
  из палитры и кнопки Explorer создаёт доску.
- Полный набор canvas-шорткатов; глобальный runtime не перехватывает их в режиме canvas.

### Настройки (п.5 ТЗ)
- 8 разделов: General, Appearance, Typography, Editor, Workspace, Privacy & Security,
  Shortcuts, About. Всё применяется мгновенно и персистится.
- 6 **реальных** тем + системная (полный набор CSS-переменных: фон, панели, карточки,
  текст, границы, кнопки, меню, модалки, редактор, canvas, выделение, контекстные меню).
- Язык RU/EN без перезапуска; строки собираются через реестр i18n — новый язык
  добавляется словарём без правок компонентов. Английский — встроенный fallback.
- Типографика: шрифты UI/редактора/моно из системного списка с fallback-проверкой,
  размер, межстрочный интервал, толщина (применяются CSS-переменными).
- Privacy: размер и список `nexus:*`-ключей, диагностика (только в памяти, выключена
  по умолчанию), экспорт/импорт бэкапа с валидацией и санитайзом, очистка временных данных,
  реальный список разрешений приложения.
- About: версии, стек, лицензии, копирование сведений; без фиктивных ссылок.

### Горячие клавиши (п.6 ТЗ)
- Shortcut Manager: список по группам, поиск, запись нового сочетания, конфликты
  (в пределах области), сброс одного/всех, восстановление по умолчанию.
- Базовый набор из ТЗ работает: Ctrl+N, Ctrl+Shift+N, Ctrl+P, Ctrl+Shift+P, Ctrl+S,
  Ctrl+W, Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+Z / Ctrl+Shift+Z, Delete, F2, Ctrl+B,
  Ctrl+, , Escape; плюс canvas-сочетания.
- Runtime учитывает контекст: не трогает ввод текста, не перехватывает сочетания редактора
  без необходимости, во время записи сочетания глобальный обработчик отключён.

### UX/UI (п.7 ТЗ)
- Единые отступы/размеры/иерархия, состояния disabled, пустые состояния, уведомления,
  кастомные скроллбары, адаптив к 4 разрешениям, подтверждения и undo для разрушительных действий.
- Стиль NEXUS сохранён (референсный layout, токены, Inter, Lucide); новых «чужих» панелей нет.
- Добавлены Error Boundary, тосты с действиями, диалог вставки ссылки, контекстные меню.

## Безопасность

Проведён полный аудит (детали — [docs/security-audit.md](security-audit.md)):
- **Приватность**: нет телеметрии/аналитики/трекеров, нет fetch/XHR/WebSocket, нет
  идентификаторов пользователя/устройства, содержимое файлов не покидает устройство;
  Rust/IPC не имеет доступа к ФС, shell, opener, updater; кастомных команд нет.
- **Tauri**: CSP для production (`default-src 'self'`, без remote origins) + отдельный
  `devCsp` для Vite; capabilities урезаны до window-контролов (minimize/maximize/
  unmaximize/close/isMaximized/startDragging/internal-toggle-maximize); `devtools: false`
  в релизе; release-сборка stripped (нет путей сборки в бинарнике).
- **Данные**: HTML заметок санитайзится (allow-list тегов/атрибутов, безопасные URL)
  при загрузке, paste, drag&drop и импорте бэкапа; бэкап ограничен 50 МБ, валидируется
  структурно (store + canvas), `settings` клэмпятся; битый/чужой payload отклоняется.
- **Persisted state**: валидация формы и нод при merge, fallback на дефолты при повреждении,
  ошибки квоты/записи не «молчат»; внешние ссылки не навигируют WebView.
- Секретов/ключей в коде и конфигах нет, `.env` отсутствует, логи не содержат путей и
  содержимого документов (dev-логи только в debug-сборке).

## Производительность

- Production-бандл: `index.js` 861 КБ (≈230 КБ gzip вместе с Konva/react-konva),
  CSS 42 КБ, `window` 15 КБ, dist 1.2 МБ (шрифты Inter woff2).
- Измерено на релизной сборке (frozen build): **~1.9 с** до `networkidle` (включая запуск
  браузера в тестовом окружении), **~10 МБ** JS heap, **565** DOM-узлов, 3 ресурсных записи,
  внешних запросов — 0.
- Оптимизации: debounce записи в localStorage 250 мс, настраиваемый debounce автосохранения
  редактора (150–600 мс по умолчанию 500 мс), `useMemo` для производных списков/backlinks,
  Konva отрисовывает сцену послойно (без React-рендера объектов на каждый кадр),
  анимации только на compositor-friendly свойствах, `prefers-reduced-motion` избегает лишних кадров.
- Потребление памяти canvas-модулем растёт с числом объектов/изображений (хранятся в localStorage);
  для больших досок рекомендуются умеренные размеры изображений.

## Известные проблемы

1. **Хранение только в localStorage**: квота браузера ограничивает объём заметок и
   особенно изображений Canvas; при переполнении запись не блокирует приложение (ошибка
   видна в консоли), но данных может не сохраниться. Решение на будущее — файловое/
   SQLite-хранилище или ограничение размера изображений.
2. **Номера строк редактора** приблизительные (по визуальным строкам блоков), т.к.
   редактор — rich contentEditable, а не построчный; стиль курсора зависит от поддержки
   CSS `caret-shape` в WebKitGTK (предусмотрен fallback).
3. **e2e window-контролов**: кнопки minimize/maximize/close вызывают Tauri API, permissions
   валидированы сборкой, но реальный клик не автоматизирован (в сессии niri нет инструмента
   инъекции ввода; ручная проверка не проводилась). Остальной hotkey/e2e слой работает.
4. **Масштаб интерфейса** реализован CSS-transform на корне: визуально и функционально
   работает (Konva корректно пересчитывает координаты указателя), но при экзотическом DPI
   может выглядеть чуть иначе, чем масштабирование нативных размеров.
5. **Производительность на больших объёмах** (тысячи документов/объектов Canvas) не
   измерялась; для текущих сценариев запас достаточный. Виртуализация дерева/списков не
   внедрялась.
6. **Canvas-изображения** вставляются через файл → data URL и хранятся в localStorage
   (ограничено квотой; большие изображения могут не сохраниться — UI предупреждает о статусе).
7. **Экспорт Canvas в PNG** реализован, но скрытые/огромные сцены могут занимать много памяти
   при экспорте (не оптимизировано тайлингом).
8. devCsp для Vite использует `unsafe-inline/unsafe-eval` (только development; production CSP
   строгий). Это осознанно.
9. **Canvas — ограничения реализации** (осознанный scope): геометрия только rect/ellipse
   (нет line/triangle/diamond/star); группировка модельная (`groupId` + multi-node
   Transformer), вложенные группы не поддерживаются; направление стрелки не реверсится,
   сторона якоря выбирается автоматически; ластик удаляет объект/связь целиком (не пиксельно);
   свободное рисование без pressure; экспорт PNG — видимой области; undo-история (40 шагов)
   хранится в памяти и не персистится; snap-to-grid и шаблоны не реализованы (P2 scope cut).
10. Canvas не персистит историю undo и может потерять последние ~0.5 с изменений
   viewport/контента при жёстком kill процесса (общий debounce-контракт 250+300 мс);
   изображения — dataURL в localStorage (квота ~5 МБ, ошибка записи только в console.warn).
